# turbo-atomizer — design spec

Date: 2026-10-10
Status: draft, revision 4 (revision 3 approved after three cold-read and critic rounds; revision 4 applies fixes F1–F4 from the verify-first spike, `docs/spikes/2026-10-11-verify-first.md`, picked by the user on 2026-10-11)
Source plan: Claude Doc "Turbo Atomizer: build plan" (spike on turbo 2.11.7, Playwright 1.64.0, 30 specs)
Reference implementation: Nx Playwright plugin, `nrwl/nx@200edc8` (`packages/playwright/src/plugins/plugin.ts`)
Playwright facts below were checked against the `playwright@1.64.0` npm tarball (`lib/…` line numbers).

## 1. Goal

Publish `turbo-atomizer`, an unscoped public npm package that turns every Playwright spec file of a Turborepo workspace package into its own turbo task. Each file then gets turbo's local and remote cache, affected-only selection, and retry-only-what-failed, without adding scripts to any `package.json`.

The first consumer has 200+ spec files and a one-hour suite that is retried whole (up to three times) on a flaky failure.

Success means:

- `turbo run e2e-ci` runs the real suite as file tasks with real browsers and one shared web server.
- With nothing changed, every cacheable file replays from cache; with no live specs, no web server starts.
- After one spec is edited, only that file runs.
- After a failed CI attempt, the retry runs only the failed files, given a cache that outlives the attempt and `--continue=dependencies-successful` on the first attempt.
- Adding or removing a spec changes no other file's hash.
- Editing the app under test invalidates every file.
- The same holds on Linux, macOS and Windows, under pnpm and npm.

## 2. Non-goals

- Sharding or spreading files over machines.
- Cypress or other runners (an adapter follows only if a Cypress suite needs it).
- Reading or writing CI vendor config. The package reads no CI variable.
- A Playwright config outside the test package root.
- The `package.json` fallback writer. Its design is recorded in section 12 so it can be built if turbo drops `command`.
- Turbo Console itself. This package only keeps the conventions the Console reads (section 9).

## 3. Settled decisions

| Topic | Decision |
|---|---|
| Unit of work | One turbo task per spec file, named `<task>--<path>` (`e2e-ci--tests/login.spec.ts`), generated by `sync` into turbo's experimental `command` field. Task-level `tags` worked in the doc's spike (`turbo query` listed them). |
| Experimental flag | Accepted. `futureFlags.experimentalTaskCommand` is set in the root `turbo.json`. Turbo is a narrow peer dependency; CI also runs against turbo `latest` to detect breakage. `futureFlags.affectedUsingTaskInputs` is set too, so `--affected` and `turbo query` `affectedTasks` select single file tasks instead of whole packages (spike item 11, F4). It changes every `--affected` run in the repo from package-level to task-level selection; docs say so. |
| Where tasks live | A generated workspace package per test package (`tools/<test-package-dir-basename>-atoms`), inherited through `extends`. The test package's own `turbo.json` is written once by `init` and never again. |
| Umbrella | `e2e-ci` (configurable). An existing `e2e` script is left alone for whole-suite runs. |
| Playwright helper | **Required.** `withAtomizer(config)` from `turbo-atomizer/playwright` wraps the consumer's config. Outside atomizer it returns the config untouched. Under `TURBO_ATOMIZER=1` it forces `reuseExistingServer: true`; under `TURBO_ATOMIZER_DESCRIBE=1` (atomizer's own `--list` runs only) it also publishes the raw config facts atomizer needs into `config.metadata['turbo-atomizer']` (section 5.2). Reason: `playwright test --list --reporter=json` reports the CLI's reporter override instead of the user's (`common/index.js:523`), `webServer: null` for an array of servers (`:542-548`), RegExp `wait` patterns as `{}`, and no project `dependencies` (`runner/index.js:4249-4261`). |
| Spec discovery | `playwright test --list --reporter=json` with `TURBO_ATOMIZER=1`. Respects per-project `testDir` / `testMatch`, drops files with zero tests. Files that belong only to setup or teardown projects (from helper metadata) are dropped. |
| File selection in exec | `--test-list <file>` holding one line: the spec path relative to Playwright's `config.rootDir`, which is `resolve(configDir, testDir)` (`common/index.js:508`). A bare path line matches every test of exactly that file (`runner/index.js:2746-2774`). Requires Playwright ≥ 1.56. Task names stay relative to the test package root. |
| Zero-test guard | `--test-list` suppresses "No tests found" (`runner/index.js:6666`), so exec adds a small counting reporter that records the tests selected in `onBegin` (skipped tests included). A run with zero selected tests fails, unless the user forwarded a filtering arg. A false green is never cached. |
| Task inputs | `$TURBO_DEFAULT$` minus every file matching the spec globs, minus snapshot folders, minus the atomizer config file. Turbo applies every negated glob after all positive ones, so the own spec cannot be re-included in the same list (spike item 1, F1). Instead each spec gets a **carrier task**: a cacheable no-op (`node -e 0`) whose inputs are only that spec and its snapshot folder. The file task depends on its carrier, and turbo folds a dependency's hash into the dependent's hash, so the own spec reaches the file task's hash. Helpers, fixtures and Playwright config are covered automatically; editing one spec reruns only that spec. Cost: 2N+1 tasks per run (spike: a fully cached 302-spec rerun takes 0.34–0.42 s instead of 0.21–0.26 s). |
| Passthrough args | `turbo run e2e-ci -- <args>` never reaches the file tasks, because turbo forwards args only to tasks named on the command line, and it hashes them into every task (spike item 2, F2). Playwright args for a whole run go in the env var `TURBO_ATOMIZER_ARGS`, which every file task lists in `env` (hashed, and passed under strict env mode). `-- <args>` stays documented only for a single file task named on the command line. |
| App under test | Must be a workspace dependency of the test package that has a task matched by the configured `dependsOn` (default `^build`), so its sources reach every file's hash. `doctor` checks this with `turbo query` and errors when the config has a web server and no workspace dependency provides such a task. |
| Uncached specs | Config patterns. Default `cache: false`; opt-in reuse within a commit through a named commit env var written into `env`. Both variants carry the `atomizer:live` tag. |
| Web server | Playwright `webServer` (single or array) stays the source of truth. A detached, refcounted supervisor shares one instance of each server across concurrent file tasks (section 7). |
| Reporters | User's configured reporters are kept. Exec redirects each built-in reporter's output per file through `PLAYWRIGHT_<R>_OUTPUT_*`; these env vars take precedence over output options in the config (`runner/index.js:1537-1541`). Exec adds blob (when the config has none) and its counting reporter in one comma-joined `--add-reporter`, because the option keeps only its last occurrence (`program.js:41-47,189`) and splits its value on commas (`cli/testActions.js:161-164`). |
| Setup work | `^build` is a task dependency. Login and similar setup is a Playwright setup project, which runs inside each file's process; doctor warns about its per-file cost. Specs never depend on other specs. |
| Merge | `turbo-atomizer merge-reports`, a plain CLI step run after the suite even when it failed. Not a turbo task. |
| Config location | `turbo-atomizer.json` in the test package (excluded from task inputs), or a `"turbo-atomizer"` key in its `package.json`. Both present is an error. Docs warn that editing the `package.json` key invalidates every file's cache, because turbo always hashes `package.json`. |
| Package managers / OS | pnpm and npm; Linux, macOS, Windows. |
| CI flags | `--continue=dependencies-successful`, so one failure does not cancel the other files (flag documented in turbo 2.11.7 `docs/reference/run.mdx:168`). `turbo run e2e-ci --affected` runs every file task whenever one is affected: the umbrella and `<task>--all` become affected through their dependencies, and turbo then runs all of their dependencies (spike item 11, F4). Affected runs therefore go through `turbo-atomizer affected` (section 6.6), which names the affected file tasks on the turbo command line. Full runs use `turbo run e2e-ci --continue=dependencies-successful`. |
| Fallback writer | Deferred, design documented only (section 12). |

## 4. What a consumer's repo looks like

Root `turbo.json` (or `turbo.jsonc`) gains two flags, set by `init`:

```json
{ "futureFlags": { "experimentalTaskCommand": true, "affectedUsingTaskInputs": true } }
```

Test package `apps/web-e2e/package.json` declares the app as a workspace dependency (`"@acme/web": "workspace:*"` under pnpm, `"*"` under npm workspaces).

Test package `apps/web-e2e/playwright.config.ts`:

```ts
import { defineConfig } from '@playwright/test';
import { withAtomizer } from 'turbo-atomizer/playwright';

export default withAtomizer(defineConfig({ testDir: './tests', webServer: { command: 'pnpm --filter @acme/web start', url: 'http://localhost:3000' } }));
```

Test package `apps/web-e2e/turbo.json`, written once by `init`:

```json
{
  "extends": ["//", "@acme/web-e2e-atoms"],
  "tasks": { "e2e-ci": { "dependsOn": ["e2e-ci--all"] } }
}
```

Generated package `tools/web-e2e-atoms/` holds a private `package.json` (`{ "name": "@acme/web-e2e-atoms", "private": true, "version": "0.0.0" }`) and the generated `turbo.json`, rewritten by every `sync`. Example for `testDir: './tests'`, `uncached.patterns: ["**/*.live.spec.ts"]`, `failOnFlaky: true`, and a config without a blob reporter:

```json
{
  "extends": ["//"],
  "tags": ["atomizer:definitions"],
  "tasks": {
    "e2e-ci--tests/checkout.live.spec.ts": {
      "command": ["node", "-e", "require('turbo-atomizer/exec')", "tests/checkout.live.spec.ts", "checkout.live.spec.ts", "--atomizer-blob", "--config=playwright.config.ts", "--fail-on-flaky-tests"],
      "dependsOn": ["^build", "e2e-ci-src--tests/checkout.live.spec.ts"],
      "inputs": [
        "$TURBO_DEFAULT$",
        "!**/*.{spec,test}.{ts,tsx,js,jsx,mts,cts,mjs,cjs}",
        "!**/*-snapshots/**",
        "!turbo-atomizer.json"
      ],
      "outputs": [".atomizer/tests-checkout-live-spec-ts-4b1622/**", "!.atomizer/tests-checkout-live-spec-ts-4b1622/test-results/**"],
      "env": ["TURBO_ATOMIZER_ARGS"],
      "cache": false,
      "tags": ["atomizer:e2e-ci", "atomizer:live"]
    },
    "e2e-ci--tests/login.spec.ts": {
      "command": ["node", "-e", "require('turbo-atomizer/exec')", "tests/login.spec.ts", "login.spec.ts", "--atomizer-blob", "--config=playwright.config.ts", "--fail-on-flaky-tests"],
      "dependsOn": ["^build", "e2e-ci-src--tests/login.spec.ts"],
      "inputs": [
        "$TURBO_DEFAULT$",
        "!**/*.{spec,test}.{ts,tsx,js,jsx,mts,cts,mjs,cjs}",
        "!**/*-snapshots/**",
        "!turbo-atomizer.json"
      ],
      "outputs": [".atomizer/tests-login-spec-ts-6b6dc3/**", "!.atomizer/tests-login-spec-ts-6b6dc3/test-results/**"],
      "env": ["TURBO_ATOMIZER_ARGS"],
      "tags": ["atomizer:e2e-ci"]
    },
    "e2e-ci-src--tests/checkout.live.spec.ts": {
      "command": ["node", "-e", "0"],
      "inputs": ["tests/checkout.live.spec.ts", "tests/checkout.live.spec.ts-snapshots/**"],
      "tags": ["atomizer:carrier"]
    },
    "e2e-ci-src--tests/login.spec.ts": {
      "command": ["node", "-e", "0"],
      "inputs": ["tests/login.spec.ts", "tests/login.spec.ts-snapshots/**"],
      "tags": ["atomizer:carrier"]
    },
    "e2e-ci--all": {
      "dependsOn": ["e2e-ci--tests/checkout.live.spec.ts", "e2e-ci--tests/login.spec.ts"]
    }
  }
}
```

Generation rules, so output is byte-identical for identical inputs:

- Tasks sorted by task name in UTF-16 code-unit order (plain `<` comparison, no locale); `<task>--all` last. File tasks (`<task>--…`) therefore precede carriers (`<task>-src--…`).
- Task keys in this order: `command`, `dependsOn`, `inputs`, `outputs`, `env`, `passThroughEnv`, `cache`, `tags`.
- Empty arrays are omitted; `cache` is emitted only when `false`.
- Two-space JSON, trailing newline: exactly `JSON.stringify(value, null, 2) + '\n'`, so every array element sits on its own line. The example above keeps short arrays on one line for reading; its content and key order are exact, its whitespace is not.
- File task `dependsOn`: the configured `dependsOn`, then its carrier's name.
- File task `inputs`: `$TURBO_DEFAULT$`, the negated `specGlobs`, the negated `snapshotGlobs`, the config-file exclusion, then `extraInputs`. The own spec is never listed (it would be negated anyway); the carrier brings it in.
- File task `env`: the configured `env`, then `uncached.commitEnv` (live specs only), then `TURBO_ATOMIZER_ARGS`; a repeated name keeps its first position.
- Carrier: name `<task>-src--<task path>`, `command` `["node", "-e", "0"]` (turbo rejects an empty-string argument), `inputs` `[<task path>, <task path>-snapshots/**]`, tag `atomizer:carrier`, no `dependsOn`, `outputs`, `env` or `cache` key. A carrier is cached even for a live spec. Its name cannot collide with a file task, whose names all start `<task>--`.
- The config-file exclusion is emitted only when the config lives in `turbo-atomizer.json`.
- With a custom `snapshotPathTemplate` or `snapshotDir`, the file task's snapshot exclusion and the carrier's snapshot input are both omitted (snapshots stay a shared input) and doctor warns.
- `<task>--all` depends on the file tasks only, never on carriers.

`.atomizer/` is added to `.gitignore` by `init`.

A CI job needs only:

```sh
turbo run build --filter=<test-package>^...                     # specs may import built workspace packages; --list loads them
npx turbo-atomizer sync --check
npx turbo-atomizer doctor
npx turbo-atomizer affected                                       # runs only the affected file tasks, --continue=dependencies-successful
npx turbo-atomizer merge-reports                                  # run even when the previous step failed
```

A job that runs the whole suite replaces the `affected` step with `turbo run e2e-ci --continue=dependencies-successful`. Playwright args for every file go in the env: `TURBO_ATOMIZER_ARGS='--grep @smoke' turbo run e2e-ci`.

`turbo run e2e-ci` runs only the test package's tasks. `turbo run e2e-ci--all` and a direct `turbo run e2e-ci--tests/login.spec.ts` also schedule the generated package's copies of those tasks (spike item 8, F3); those copies exit 0 without running anything (section 6.3 step 1). `--filter=<test-package>` avoids scheduling them.

## 5. Config and helper

### 5.1 Atomizer config

Validated with zod at load; a JSON schema is generated from the same zod schema with `z.toJSONSchema` and shipped as `turbo-atomizer/schema.json`.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `task` | string | `"e2e-ci"` | Umbrella name and task-name prefix. |
| `generatedPackage` | string | `tools/<test-package-dir-basename>-atoms` | Path of the generated package, relative to the workspace root. Written by `init`. |
| `playwrightConfig` | string | first of `playwright.config.{ts,js,mts,mjs,cts,cjs}` | Config file name, in the test package root. |
| `specGlobs` | string[] | `["**/*.{spec,test}.{ts,tsx,js,jsx,mts,cts,mjs,cjs}"]` | Excluded from every task's inputs. Every discovered spec must match one (checked by `sync` and `doctor`). |
| `snapshotGlobs` | string[] | `["**/*-snapshots/**"]` | Excluded from every task's inputs when the default snapshot template and `snapshotDir` are in use; the task's own `<spec>-snapshots/**` reaches its hash through the carrier. |
| `extraInputs` | string[] | `[]` | Copied verbatim into every task's `inputs`, in turbo glob syntax (files outside the package use `$TURBO_ROOT$/…`). doctor resolves `$TURBO_ROOT$` against the workspace root and other entries against the package dir. |
| `env` | string[] | `[]` | Hashed env vars (base URL, feature flags). `TURBO_ATOMIZER_ARGS` is always added (section 4). |
| `passThroughEnv` | string[] | `[]` | Unhashed env vars the server or tests need under turbo's strict env mode. |
| `dependsOn` | string[] | `["^build"]` | Dependencies of every file task. |
| `uncached.patterns` | string[] | `[]` | Specs matching these carry `atomizer:live` and get `cache: false`. |
| `uncached.commitEnv` | string | unset | If set, live specs stay cacheable with this var in `env` instead, so reuse is limited to one commit. |
| `failOnFlaky` | boolean | `false` | Adds `--fail-on-flaky-tests` so a flaky pass is not stored. |
| `server.idleMs` | number | `5000` | Supervisor stops its servers after this long with no connected exec. |

Lookup in the test package: `turbo-atomizer.json`, then the `"turbo-atomizer"` key in `package.json`. Both present → `ConfigConflictException`. Neither → defaults (`init` writes the file).

### 5.2 `withAtomizer(config)`

Exported from `turbo-atomizer/playwright` (ESM and CJS). Behaviour:

- `TURBO_ATOMIZER` unset: returns `config` unchanged.
- `TURBO_ATOMIZER=1` (every Playwright run atomizer starts): sets `reuseExistingServer: true` on every `webServer` entry.
- `TURBO_ATOMIZER_DESCRIBE=1` (set only for the `--list` runs of `sync`, `doctor`, `merge-reports` and the supervisor, never for test runs, so nothing lands in blobs, HTML reports or the cache): also sets `config.metadata['turbo-atomizer']` to a JSON-serializable object:
    - `version: 1`
    - `reporters`: the configured reporters as `[name, options]` pairs, defaults resolved the way Playwright resolves them.
    - `setupProjects`: names of projects referenced by any project's `dependencies` or `teardown`.
    - `snapshotPathTemplates` and `snapshotDirs`: top-level and per-project values, `null` when unset.
    - `webServers`: one entry per server with `command`, `url`, `port`, `cwd` (raw; the supervisor resolves it against the config dir, which is the package root, as Playwright does at `runner/index.js:841`), `env`, `timeout`, `ignoreHTTPSErrors`, `gracefulShutdown`, and `wait.stdout` / `wait.stderr` as `{ source, flags }`.
- `TURBO_ATOMIZER_DESCRIBE=1` and `TURBO_ATOMIZER_SERVER_ENV=1` (set only by the supervisor): additionally records `serverEnv`, the `process.env` seen at config load (after any dotenv the config ran). This never leaves the supervisor's memory.

`sync`, `doctor`, `merge-reports` and the supervisor read this metadata from the `--list --reporter=json` output (`config.metadata`). Missing metadata → `HelperMissingException` with the one-line fix.

## 6. Commands

All commands accept `--package <dir>` to choose one test package; without it they operate on every package that has an atomizer config (`init` instead uses the cwd if it contains a Playwright config, and errors otherwise). CLI parsing uses `node:util` `parseArgs`. Playwright is run as `process.execPath <bin>`, where `<bin>` is `bin.playwright` of `@playwright/test/package.json` resolved from the test package (`require.resolve(…, { paths: [packageDir] })`).

### 6.1 `init [--package <dir>] [--generated-dir <dir>]`

Idempotent: each step checks before it writes. JSON files are edited with `jsonc-parser` (keeps comments, accepts `turbo.jsonc`); `pnpm-workspace.yaml` with `yaml`'s document API (keeps comments).

1. Detect the package manager from the lockfile (`pnpm-lock.yaml` or `package-lock.json`); anything else is an error.
2. Check turbo and Playwright versions against the peer ranges (each read from its `package.json`, resolved from the workspace root and the test package): turbo or Playwright below the minimum is an error and init stops before writing anything; turbo above the tested range is a warning.
3. Write `turbo-atomizer.json` if no config exists.
4. Derive the generated package: name `<test-package-name>-atoms` (scope kept: `@acme/web-e2e` → `@acme/web-e2e-atoms`); dir `--generated-dir` or `tools/<test-package-dir-basename>-atoms`. Error if that dir exists and is not an atomizer package for this test package.
5. Create the generated package: `package.json` and a `turbo.json` that already holds `"tags": ["atomizer:definitions"]` and `"<task>--all": {}`, so a failure in a later step leaves a valid task graph.
6. Make sure the workspace globs (`pnpm-workspace.yaml` `packages`, or root `package.json` `workspaces`) cover the generated dir; add its path if not.
7. Set `futureFlags.experimentalTaskCommand` and `futureFlags.affectedUsingTaskInputs` in the root `turbo.json`/`turbo.jsonc`. (Part of turbo's global hash, so this one-time edit misses every cache once; docs say so. The second flag makes every `--affected` run in the repo select by task inputs; docs say so.)
8. Test package `turbo.json`:
   - absent → create it as in section 4;
   - `extends` present without the generated name → append it;
   - `<task>` task present and already depending on `<task>--all` → leave it; present with other content → error with the exact edit to make (never overwrite);
   - a `package.json` script named `<task>` → error (turbo would run the script after the file tasks; seen in the doc's spike).
9. Add `turbo-atomizer` as a root devDependency at `^<version of the running CLI>` unless the root already lists it under any spec (a tarball or `workspace:` spec is kept), and `.atomizer/` plus `playwright.atomizer-merge.config.mjs` to `.gitignore` (so a leftover merge config never enters `$TURBO_DEFAULT$`).
10. Run the package manager's install once so the lockfile includes the generated package (`npm ci` refuses otherwise). Skipped when steps 3–9 changed no file, so a re-run of `init` installs nothing.
11. Run `sync` only if the Playwright config already carries the helper metadata. Otherwise skip it and exit 0 with the remaining steps: wrap the config in `withAtomizer`, declare the app as a workspace dependency, build workspace dependencies, run `turbo-atomizer sync`. init never edits the Playwright config.
12. Print what changed and that the lockfile must be committed.

### 6.2 `sync [--check]`

1. Load config.
2. Run `playwright test --list --reporter=json --config=<playwrightConfig>` in the test package with `TURBO_ATOMIZER=1` and `TURBO_ATOMIZER_DESCRIBE=1`. Read `config.rootDir`, `config.metadata['turbo-atomizer']` and the spec files.
3. Drop files whose tests all belong to `setupProjects`.
4. Reject any spec outside the package root, any spec not matched by `specGlobs`, and any list line Playwright would misparse (`runner/index.js:2749-2759`): starting with `[` or `#`, containing `>` or `›`, or ending in `:<digits>`. Also reject any task path containing a glob metacharacter (`*`, `?`, `[`, `]`, `{`, `}`, `!`): the own-spec input entry is written verbatim and must match only that file. The error names the file and asks for a rename.
5. For each spec compute: task name (posix path relative to the package root), list line (posix path relative to `config.rootDir`), slug, exec flags (`--atomizer-blob` when `reporters` has no blob), fixed Playwright args (`--config=<playwrightConfig>`, `--fail-on-flaky-tests` when `failOnFlaky`).
6. Build the generated `turbo.json` (pure function, section 4): one file task and one carrier per spec, plus `<task>--all`.
7. Without `--check`: write it if the bytes differ. With `--check`: exit 1 and print a summary (added, removed, changed tasks) if they differ. The summary lists file tasks only, selected by the `atomizer:<task>` tag; a carrier changes only together with its file task.

Slugs: the package-relative path with `/`, `\` and `.` replaced by `-`, plus the first 6 hex chars of a sha1 of that path, so `a-b.spec.ts` and `a/b.spec.ts` cannot collide.

`sync` loads the specs, so workspace packages they import must be built first (CI recipe, section 4).

### 6.3 `exec` (internal)

Entry `turbo-atomizer/exec`, built as CommonJS so the generated `require()` works under pnpm and npm. turbo runs it with the test package as cwd. Its argv is: `<task path> <list line> [exec flags…] [fixed Playwright args…] [args forwarded by turbo…]`. Exec flags start with `--atomizer-` and are consumed by exec; the only one in v1 is `--atomizer-blob`. exec reads no atomizer config. Node puts the args after `-e <code>` at `process.argv.slice(1)`.

`TURBO_ATOMIZER_ARGS` holds extra Playwright args for every file task. A value whose first non-space character is `[` is parsed as a JSON array of strings (for args containing spaces); any other value is split on runs of whitespace. Unset or blank means no args. An invalid JSON value fails the run with a message naming the variable.

1. If the cwd has no Playwright config and its `turbo.json` carries the tag `atomizer:definitions`, the task is the generated package's copy (turbo schedules it for `<task>--all` and direct runs without `--filter`, spike item 8): print one line, `turbo-atomizer: skipped <task path> in the generated package; add --filter=<test package> to avoid scheduling it`, and exit 0 before any other step. Turbo caches the no-op. If the cwd has no Playwright config otherwise, fail with "run from the test package". Then fail with "run turbo-atomizer sync" if `<task path>` does not exist.
2. Delete `.atomizer/<slug>/` so no stale report survives.
3. Connect to the supervisor (section 7), spawning it if needed; wait for `ready` and hold the connection open until Playwright exits. On `failed`, print the message and log tail and exit 1.
4. Write `.atomizer/<slug>/test-list.txt` containing the list line.
5. Spawn `playwright test --test-list .atomizer/<slug>/test-list.txt --output .atomizer/<slug>/test-results --add-reporter=<list>` followed by the fixed args, the `TURBO_ATOMIZER_ARGS` args, and the turbo-forwarded args, the last two minus any `--add-reporter`. `<list>` joins with commas: `blob` (if `--atomizer-blob`), the absolute path of the counting reporter, and the values of any `--add-reporter` from `TURBO_ATOMIZER_ARGS` and then from the forwarded args.
6. Env: the supervisor's `ready.env` (values captured from named groups in `wait` patterns, which Playwright would otherwise put into the test env), then `TURBO_ATOMIZER=1`, `PLAYWRIGHT_BLOB_OUTPUT_FILE=.atomizer/<slug>/blob.zip`, `PLAYWRIGHT_HTML_OUTPUT_DIR=.atomizer/<slug>/html`, `PLAYWRIGHT_HTML_OPEN=never`, `PLAYWRIGHT_JSON_OUTPUT_FILE=.atomizer/<slug>/report.json`, `PLAYWRIGHT_JUNIT_OUTPUT_FILE=.atomizer/<slug>/junit.xml`, `TURBO_ATOMIZER_COUNT_FILE=.atomizer/<slug>/count.json` (where the counting reporter writes `{ "selected": n }`).
7. Forward SIGINT and SIGTERM to Playwright.
8. Exit code: Playwright's code; a death by signal maps to 128 + signal number (1 if unknown). If Playwright exited 0: a missing `count.json` fails the run; `selected: 0` fails it with "no tests selected for <task path>; run turbo-atomizer sync", unless a filtering arg was forwarded or came from `TURBO_ATOMIZER_ARGS` (`-g`/`--grep`, `-G`/`--grep-invert`, `--project`, `--last-failed`, `--only-changed`, `--shard`, or any positional arg; a shard may legitimately hold no test of this file). Forwarded args are parsed against Playwright's test options (`program.js:188ff`): a token directly after an option declared with a `<value>` is that option's value; a token directly after an option declared with an optional `[value]` (`--only-changed`, `--shuffle`, `-u`/`--update-snapshots`, `--debug`) is its value when it does not start with `-` (commander's rule); a variadic `<value...>` option (`--project`) takes every following token up to the next one starting with `-`; any other bare token is positional. Short and long forms (`-c`/`--config`, `-g`/`--grep`, `-G`/`--grep-invert`, `-j`/`--workers`) are both recognised, as are `--opt=value` and an attached short value (`-gfoo`). Step 5's removal of a forwarded `--add-reporter` uses the same parsing. `TURBO_ATOMIZER_ARGS` and the forwarded args are parsed as one list, env args first.

### 6.4 `doctor`

Fails (exit 1) on any error, prints warnings otherwise:

- Error: generated file stale (same as `sync --check`).
- Error: helper metadata missing (config not wrapped in `withAtomizer`).
- Error: test package `turbo.json` no longer extends the generated package or its `<task>` no longer depends on `<task>--all` (e.g. after renaming `task`).
- Error: root future flag `experimentalTaskCommand` missing, or turbo/Playwright below the minimum.
- Warning: root future flag `affectedUsingTaskInputs` missing; `turbo-atomizer affected` then runs every file task of an affected package.
- Error: a spec not matched by `specGlobs`, or outside the package root.
- Error: a web server entry with neither `url` nor `port` (it cannot be shared; every file run would start its own copy, `runner/index.js:859`).
- Error: the config has a web server, no workspace dependency of the test package has a task matched by the configured `dependsOn` (checked with `turbo query`), and no non-negated `extraInputs` entry reaches outside the package; the message suggests adding a build task or `extraInputs`.
- Error: a spec whose imports (from `turbo query` file dependencies) reach a file outside the package that is neither in a workspace dependency that has a task matched by `dependsOn` nor covered by `extraInputs`.
- Warning: setup projects present; they run once per file.
- Warning: custom `snapshotPathTemplate` or `snapshotDir`; snapshots are a shared input.
- Warning: turbo outside the tested range.
- Warning: a custom (non-built-in) reporter is configured; it gets no per-file output redirect, so it must not write to a fixed path.

### 6.5 `merge-reports`

1. Resolve the helper metadata with a `--list` run under `TURBO_ATOMIZER_DESCRIBE=1`. For each test package, collect `.atomizer/<slug>/blob.zip` for the slugs in the current generated file only.
2. Warn when the number of blobs differs from the number of file tasks, counted by the `atomizer:<task>` tag so carriers are excluded (expected in an affected run; the message says so). Zero blobs: warn and exit 0.
3. Copy each blob into a temp folder as `<slug>.zip`.
4. Write a temporary merge config next to the Playwright config (`playwright.atomizer-merge.config.mjs`, deleted afterwards) whose `reporter` is the helper's `reporters` with `blob` removed, options intact, and `testDir` matching the original. Writing it in the config dir keeps relative reporter output paths where the user expects them.
5. Run `playwright merge-reports <temp folder> --config <merge config>` (1 when the merged report has failures, `reportActions.js:58`).

Steps 1–5 run once per test package. The command exits non-zero if any package's merge exits non-zero.

Local runs may merge blobs from earlier runs of tasks that this run did not select; CI on a fresh checkout does not. Docs say so.

### 6.6 `affected [--package <dir>] [-- <turbo run args…>]`

Runs only the affected file tasks, because `turbo run e2e-ci --affected` cannot select a subset (section 3, CI flags). Per test package:

1. Load config; read the test package's name from its `package.json`.
2. From the workspace root, run `turbo query` with `{ affectedTasks(taskFilter: { has: { field: TAG, value: "atomizer:<task>" } }) { items { fullName } } }`. Keep the items whose `fullName` starts with `<test package name>#` (the generated package's copies carry the same tag) and strip that prefix. Base and head come from turbo's defaults and `TURBO_SCM_BASE` / `TURBO_SCM_HEAD`, as for `--affected`.
3. None → print `no affected file tasks in <test package name>` and continue (a passing no-op).
4. Otherwise run, from the workspace root with inherited stdio, `turbo run <task names…> --filter=<test package name> --continue=dependencies-successful` followed by the args after `--`. turbo is run as `process.execPath <bin>`, `<bin>` being `bin.turbo` of `turbo/package.json` resolved from the workspace root. Named tasks get no `--affected`; their dependencies (carriers, `^build`) run or replay as usual.

The command exits with the first non-zero turbo exit code, else 0. A long name list may hit the Windows command-line limit (about 32 K characters, roughly 800 tasks at 40 characters each; inferred, checked with the platform matrix).

## 7. Shared web server

turbo cannot keep one server alive for many tasks (`with` and gate tasks both stopped it early in the doc's spike), so servers live outside turbo's task lifetime, in a supervisor process.

**Rendezvous.** One supervisor per test package, keyed by a hash of the package's absolute path:

- POSIX: Unix socket `<os.tmpdir()>/ta-<hash12>.sock` (short, within macOS's 104-byte limit), guarded by `<…>.lock` created with `O_EXCL`. The lock holds the owner's pid and process start time. A lock whose owner is gone (pid dead, or start time differs, which covers pid reuse) is taken over atomically: `rename` it to `<…>.lock.<mypid>.stale`, continue only if the rename succeeded, then retry the `O_EXCL` create once. Independently, a supervisor unlinks an existing socket file only after connecting to it fails with `ECONNREFUSED`, so a live supervisor's socket is never removed even if two takeovers race.
- Windows: named pipe `\\.\pipe\turbo-atomizer-<hash12>`; a second `listen` fails with `EADDRINUSE`, no lock file needed.

Protocol: newline-delimited JSON from supervisor to client: `{"state":"starting"}` (repeated every 5 s while starting), `{"state":"ready","env":{…}}`, or `{"state":"failed","message":"…","logTail":"…"}`.

**Start.**

1. exec connects. On no listener, it spawns the supervisor detached (`process.execPath <supervisor entry> <package dir> <playwright config file>`; the supervisor loads the atomizer config itself for `server.idleMs`; `detached: true`, stdio to `.atomizer/server.log`, which exec opens for append after creating `.atomizer/` if missing, `windowsHide: true`, `unref()`), then retries the connection with backoff for up to 10 s.
2. A spawned supervisor takes the lock (POSIX) before unlinking any stale socket and binding; losing the lock or the bind means another supervisor won, and it exits.
3. exec waits for `ready` or `failed` without its own timeout while `starting` messages arrive; 30 s of silence counts as failure.

**Supervisor.**

1. Resolve the config in the task's real env: `playwright test --list --reporter=json --config=<file> --test-list <empty file>` with `TURBO_ATOMIZER=1`, `TURBO_ATOMIZER_DESCRIBE=1` and `TURBO_ATOMIZER_SERVER_ENV=1`, then read `webServers` and `serverEnv` from the helper metadata.
2. No servers → `ready` immediately. A server with neither `url` nor `port` → `failed` (it cannot be shared).
3. For each server: probe first. If it already answers, reuse it and never stop it (Playwright's `reuseExistingServer` semantics). Otherwise spawn `command` with `shell: true`, `cwd` from metadata, env `{ BROWSER: 'none', FORCE_COLOR: '1', DEBUG_COLORS: '1', ...serverEnv, ...entry.env }` (Playwright's defaults, `runner/index.js:824-828`), and on POSIX `detached: true` so it leads its own process group. Watch `wait.stdout` / `wait.stderr` patterns; capture their named groups for `ready.env`.
4. Probe until ready or `timeout` (default 60 s), with Playwright/Nx semantics: `port` → TCP connect to 127.0.0.1 and ::1; `url` → GET, status 200–403 is ready, a 404 on `/` retries `/index.html`, follow redirects, honour `ignoreHTTPSErrors`; retry after 100, 250, 500 ms, then every 1 s.
5. On a spawned server's early exit or timeout → `failed` with the last 50 log lines. The supervisor keeps answering `failed` for `server.idleMs`, so concurrent execs fail the same way, then exits; the next run tries again.

**Stop.**

- Each connected exec is one lease. A crashed exec drops its socket, so leases cannot go stale.
- With zero leases for `server.idleMs`, the supervisor enters `stopping` and keeps listening. For each server it started: send `gracefulShutdown.signal` (default `SIGTERM`) to the process group on POSIX (`kill(-pid, …)`), wait `gracefulShutdown.timeout` (default 5 s), then `SIGKILL`; on Windows run `taskkill /pid <pid> /T /F`.
- A client that connects while `stopping` waits. Once the servers have exited, the supervisor either restarts them (clients waiting) or releases the lock, closes the socket and exits.

A fully cached run spawns no exec, so no server starts.

Known limits, documented:

- A server reused from a previous run within its idle window, or a server the user left running, serves whatever code it was started with; atomizer cannot see that.
- Two test packages whose servers share a port: the second package reuses the first one's server, which stops when the first supervisor goes idle. Give each test package its own port.

## 8. Correctness rules

A task whose inputs miss a file can replay an old pass after that file changes. These rules come before speed.

- Inputs are the whole package minus all specs, plus the own spec through its carrier (section 3), so new helpers are covered without configuration and an edited spec never replays its old pass.
- The app under test and any other outside code reach the hash through workspace dependencies and `dependsOn` tasks, or `extraInputs`; doctor catches spec imports that do neither and a web server whose app no dependency task covers.
- turbo adds the package's `package.json` and the lockfile, so a Playwright or turbo-atomizer upgrade invalidates every file.
- turbo stores only successful tasks. A flaky pass is stored unless `failOnFlaky` is set. A run with zero selected tests fails unless a filter was forwarded (section 6.3).
- Live-backend specs are uncached by default.
- Specs must not depend on each other: any order, any concurrency, any subset.
- Concurrency: turbo's `--concurrency` (default 10) sets how many files run at once. A file runs in one Playwright worker unless the config sets `fullyParallel`; docs advise `--concurrency` near the CPU count.
- Stored passes should expire: Vercel expires after 7 days; a self-hosted cache needs its own limit. Docs only.

## 9. Console contract

Stable across minor versions; changing any of these is a major release.

- Every file task carries the tag `atomizer:<task>`; live specs also carry `atomizer:live`. File tasks are identified by this tag, never by name prefix.
- Every carrier carries the tag `atomizer:carrier` and never `atomizer:<task>`. Carrier name `<task>-src--<posix path relative to the test package>`.
- One aggregate task per group, `<task>--all`, depends on all its file tasks (not on carriers).
- File task name `<task>--<posix path relative to the test package>`.
- The generated package carries the tag `atomizer:definitions`. It also lists every file task and carrier (turbo shows tasks with an explicit `command`), so consumers read file tasks from packages without that tag.

The Console reads file tasks from `turbo query`, cache state from `turbo run <task> --dry=json`, and last results from `.turbo/runs`. Carriers keep real hashes and cache state in `--dry=json` (spike F1 follow-up).

## 10. Repository and code structure

Mirrors `lint-suite` as of `ecf0c43`: an Nx workspace, pnpm workspace with strict catalogs, packages under `packages/`, build and release scripts in a `tools` workspace package.

      src/

        playwright.ts          composition root: withAtomizer (ESM + CJS output)

        shared/
          config/              zod schema (common), loader (data-access)
          playwright/          list / test / merge-reports process calls (data-access), helper metadata (utils)
          server/              ServerLease type shared by exec/ and server/ (common)

  nx.json  tsconfig.base.json  eslint.config.base.ts  vitest.config.ts  .prettierrc  pnpm-workspace.yaml

Inside each slice, artification layers apply: `feature/` (command handlers), `domain-logic/` (orchestration and policy), `data-access/` (fs, child processes, sockets), `utils/` (pure functions such as task generation, slugging, diffing, glob matching), `common/` (types, constants such as tag names, exception classes), `config/` (the `TURBO_ATOMIZER*` env readers). Imports flow `feature → domain-logic → data-access → utils → common`, enforced by lint-suite's `boundaries` config. Only erasable TypeScript syntax, no `as` casts, explicit return types, source files under 150 lines.

Runtime dependencies: `zod`, `jsonc-parser`, `yaml`. Everything else is stdlib (`node:util` `parseArgs`, `node:net`, `node:child_process`, `node:crypto`, `node:path` `matchesGlob`). Peer dependencies: `turbo` (`>=2.11.7 <2.12.0` initially), `@playwright/test` (`>=1.56.0`).
